# Repository Guidelines

## Project Structure & Module Organization
- `src/` contains application code: `dictate.py` (main tray/hotkey app), `calibrate.py` (noise-gate calibration), `speak.py` (TTS utility), and `config.example.py`.
- `src/config.py` is generated by `install.bat` for local settings; treat it as machine-specific runtime config.
- `tests/` contains `pytest` suites (`test_dictate.py`, `test_calibrate.py`) plus shared fixtures in `conftest.py`.
- Root scripts are Windows-first operational entry points: `install.bat`, `start-dictation.bat`, `test-install.bat`, `launch.cmd`, and `uninstall.bat`.
- Reference docs live at `README.md` and `TESTING-PLAN.md`.

## Build, Test, and Development Commands
- `install.bat`: create/update `.venv`, install `requirements.txt`, and generate `src/config.py`.
- `test-install.bat`: validate environment, dependencies, GPU/CPU mode detection, and microphone visibility.
- `.venv\Scripts\python -m pytest tests/ -v`: run automated test suite.
- `.venv\Scripts\python src\dictate.py`: run app in console for debugging.
- `start-dictation.bat`: launch background `pythonw` tray app.
- `.venv\Scripts\python src\calibrate.py`: run calibration workflow for `NOISE_GATE_THRESHOLD`.

## Coding Style & Naming Conventions
- Use Python with four-space indentation and follow existing naming: `snake_case` for functions/variables, `UPPER_SNAKE_CASE` for constants.
- Keep Windows compatibility in mind (paths, process checks, tray behavior, hotkeys).
- Preserve current script style: concise module docstrings, targeted inline comments, and explicit error handling around hardware APIs.
- For batch scripts, keep environment variables uppercase and keep user prompts clear and idempotent.

## Testing Guidelines
- Framework: `pytest`.
- Test files follow `test_*.py`; test classes use `Test*`; test functions use `test_*`.
- Prioritize deterministic tests that mock hardware-facing modules (`sounddevice`, `keyboard`, tray integrations).
- For behavior touching mic/device switching, restart, or lock-file handling, run both `pytest` and relevant manual checks from `TESTING-PLAN.md`.

## Commit & Pull Request Guidelines
- Current history uses short imperative subjects (for example: `Add ...`, `Fix ...`, `Move ...`); keep that pattern.
- Keep commits focused by concern (device handling, startup flow, tests, docs).
- PRs should include: problem statement, change summary, verification steps (`pytest` command and result), and any manual validation notes for tray/hotkey/microphone flows.
- Link related issue(s) and call out config or migration impacts explicitly.
